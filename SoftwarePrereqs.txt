4. Recommended Local Setup
--------------------------

Create and activate a Python virtual environment:

macOS / Linux:

python3 -m venv .venv
source .venv/bin/activate

Windows:

python -m venv .venv
.venv\Scripts\activate

Install dependencies:

pip install -r requirements.txt

5. Environment Variables
------------------------
The repository includes .env.example showing the required production-style
environment variables.

Important variables include:

DJANGO_SECRET_KEY
DJANGO_DEBUG
DJANGO_ALLOWED_HOSTS
DJANGO_CSRF_TRUSTED_ORIGINS
DJANGO_SECURE_SSL_REDIRECT
DJANGO_SECURE_HSTS_SECONDS
DJANGO_SECURE_HSTS_INCLUDE_SUBDOMAINS
DJANGO_SECURE_HSTS_PRELOAD
DATABASE_URL
DEEPSEEK_API_KEY
DEEPSEEK_MODEL

The .env.example file contains placeholder values only.

A real DEEPSEEK_API_KEY is required for DeepSeek-based prioritisation,
low-coverage AI-assisted prioritisation, and DeepSeek-generated learning roadmaps.
Set DEEPSEEK_MODEL=deepseek-flash; this is also the code default when unset.
The OpenAI Python SDK connects to https://api.deepseek.com with the DeepSeek key.

Inject these variables into the process environment before starting Django.
The application does not automatically load .env files, so copying .env.example
alone does not configure the running process. Do not put real keys in source files.

No production API keys, passwords or other secrets are included in the
submission package.

6. Database Setup
-----------------
For local development, Django can use SQLite.

Create/apply the database schema with:

python manage.py migrate

The local db.sqlite3 development database is not required because the schema
can be reconstructed from the included Django migrations.

Production deployment uses PostgreSQL through DATABASE_URL.

7. Run the Application Locally
------------------------------
After installing dependencies and running migrations:

python manage.py runserver

The default Django development server will normally be available at:

http://127.0.0.1:8000/

A different port can be selected if required, for example:

python manage.py runserver 8001

8. System Check

9. Automated Tests
------------------
Run:

python manage.py test

The latest full test run after the DeepSeek migration passed 345 tests,
including 69 AI service and boundary tests. The original submission passed
333 automated tests.

Live AI functionality requires DEEPSEEK_API_KEY and network access. Automated
AI tests use SDK mocks or a local HTTP mock transport and require neither a real
API key nor external AI requests. Local real-API validation has confirmed both
prioritisation and learning-roadmap generation work with DeepSeek.

10. Production Deployment
-------------------------
The final production application was deployed on Railway using:

Django
Gunicorn
WhiteNoise
PostgreSQL

Production-sensitive settings are supplied through environment variables rather
than hard-coded credentials.

To deploy the current DeepSeek integration, install the current requirements
(including the OpenAI Python SDK) and supply DEEPSEEK_API_KEY and
DEEPSEEK_MODEL=deepseek-flash to the application service. AI requests use a
45-second SDK timeout, max_retries=0 and non-streaming JSON mode. Check the
production worker timeout against the expected request duration before rollout.
The DeepSeek migration has been validated locally; Railway has not yet been
updated as part of this migration.

Live application at the time of submission:

https://fitgap-ai.up.railway.app/
